# newyear

HTTP-сервис на Go, который считает, сколько календарных дней осталось до ближайшего Нового года (1 января следующего года).

- `31 декабря` → `1`
- `1 января` → `365` (в високосный год — `366`)
- Время суток не учитывается, учитывается только календарная дата.

## Требования

- Go **1.24** или новее (CI использует последнюю стабильную версию)
- (опционально) Docker — для запуска в контейнере

## Структура проекта

```
cmd/server/          точка входа: HTTP-сервер
internal/countdown/  расчёт дней до Нового года (не зависит от HTTP)
internal/api/        HTTP-обработчики, логирование запросов
.github/workflows/   CI (GitHub Actions)
```

## Сборка

```sh
go build -o bin/server ./cmd/server
```

## Запуск

```sh
./bin/server            # слушает :8080
ADDR=:9000 ./bin/server # другой адрес
```

Или без предварительной сборки:

```sh
go run ./cmd/server
```

Переменные окружения:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `ADDR` | `:8080` | адрес, на котором слушает сервер |
| `TZ`   | часовой пояс системы | часовой пояс для определения «сегодняшней» даты, например `Asia/Irkutsk` |

Сервер пишет структурированные логи (JSON, `log/slog`) в stdout — по строке на каждый запрос. Завершается корректно по `Ctrl+C` / `SIGTERM`.

### Docker

```sh
docker build -t newyear .
docker run --rm -p 8080:8080 -e TZ=Asia/Irkutsk newyear
```

## HTTP API

Все ответы — JSON (`Content-Type: application/json; charset=utf-8`).

### `GET /api/v1/new-year`

Количество дней до следующего Нового года.

**Параметры запроса**

| Параметр | Обязательный | Формат | Описание |
|---|---|---|---|
| `date` | нет | `YYYY-MM-DD` (ISO 8601) | дата, от которой считать. Если параметр не передан — используется текущая дата сервера |

**Успешный ответ — `200 OK`**

```sh
curl 'http://localhost:8080/api/v1/new-year?date=2024-02-29'
```

```json
{"date":"2024-02-29","next_new_year":"2025-01-01","days_left":307}
```

| Поле | Тип | Описание |
|---|---|---|
| `date` | string, `YYYY-MM-DD` | дата, от которой выполнен расчёт |
| `next_new_year` | string, `YYYY-MM-DD` | ближайшее следующее 1 января |
| `days_left` | integer | количество дней до него |

**Ошибки**

| Код | Когда |
|---|---|
| `400 Bad Request` | `date` передан, но пустой, в другом формате или не существует (например `2025-02-29`) |
| `404 Not Found` | неизвестный путь |
| `405 Method Not Allowed` | метод отличается от `GET` / `HEAD` |

Тело ошибки `400`:

```json
{"error":"invalid date \"2025-02-29\": expected format YYYY-MM-DD"}
```

### `GET /healthz`

Проверка работоспособности (liveness probe для Docker/Kubernetes/балансировщика).

```json
{"status":"ok"}
```

Код `200` означает, что процесс жив и обрабатывает запросы. У сервиса нет внешних зависимостей (БД и т.п.), поэтому проверять больше нечего; JSON выбран для единообразия с основным API.

## CI

Workflow `.github/workflows/ci.yml` запускается при push в `main` и на каждый Pull Request:

| Проверка | Команда |
|---|---|
| Форматирование | `gofmt -l .` (падает, если список не пуст) |
| Статический анализ | `go vet ./...` |
| Зависимости | `go mod tidy -diff`, `go mod verify` |
| Сборка | `go build ./...` |
| Тесты + гонки + покрытие | `go test -race -coverprofile=coverage.out ./...` |
| Бенчмарк (smoke) | `go test -bench=. -benchtime=100x` |
| Уязвимости | `govulncheck ./...` |
| Docker | сборка образа и запрос к запущенному контейнеру |

Отчёт о покрытии выводится в summary запуска и сохраняется как артефакт `coverage`.
